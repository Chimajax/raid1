# QuadChecker - Review Notes

## What is QuadChecker?

QuadChecker is a program that receives a rectangle pattern through standard input (stdin) and determines which Quad function generated it.

Example:

```bash
./quadA 3 3 | go run .
```

Output:

```text
[quadA] [3] [3]
```

The program identifies:

* Which Quad generated the pattern.
* The width of the rectangle.
* The height of the rectangle.

---

## What does the program do internally?

The program:

1. Reads the entire input from stdin.
2. Calculates the width and height of the rectangle.
3. Converts the input into a grid.
4. Compares the grid against the rules of QuadA, QuadB, QuadC, QuadD, and QuadE.
5. Prints every matching Quad.

Example:

```text
A
```

This can be generated by:

* QuadC(1,1)
* QuadD(1,1)
* QuadE(1,1)

Output:

```text
[quadC] [1] [1] || [quadD] [1] [1] || [quadE] [1] [1]
```

---

## Why do we use stdin?

The subject requires the program to receive input through a pipe.

Example:

```bash
./quadA 5 3 | go run .
```

The output of quadA becomes the input of QuadChecker.

This is why we use:

```go
io.ReadAll(os.Stdin)
```

to read the pattern.

---

## What is a pipe (|)?

A pipe sends the output of one command into another command.

Example:

```bash
./quadA 5 3 | go run .
```

Without a pipe:

```bash
./quadA 5 3
```

prints the rectangle.

With a pipe:

```bash
./quadA 5 3 | go run .
```

the rectangle is sent directly into QuadChecker.

---

## How do we find the width and height?

Example input:

```text
ABC
B B
CBA
```

Width:

* Count characters in the first line.
* Width = 3

Height:

* Count the number of lines.
* Height = 3

---

## Why do we split the input into lines?

We need to examine the rectangle row by row.

Example:

```go
lines := strings.Split(input, "\n")
```

Result:

```go
[]string{
    "ABC",
    "B B",
    "CBA",
}
```

This makes it easier to analyze.

---

## Why convert the input into a grid?

The grid allows direct access to any character.

Example:

```text
ABC
B B
CBA
```

becomes:

```go
[][]rune{
    {'A','B','C'},
    {'B',' ','B'},
    {'C','B','A'},
}
```

Now we can inspect any position using:

```go
grid[row][column]
```

---

## Why do we use runes instead of bytes?

A rune represents a character in Go.

Using runes is safer because Go strings are UTF-8.

Example:

```go
[]rune(line)
```

Even though the subject only uses ASCII characters, using runes is good practice.

---

## What are QuadA, QuadB, QuadC, QuadD and QuadE?

They are different rectangle generators.

Each one uses different corner characters.

### QuadA

Corners:

```text
o--o
|  |
o--o
```

Uses:

* o
* *
* |

---

### QuadB

Corners:

```text
/**\
*  *
\**/
```

Uses:

* /
* \
* *

---

### QuadC

Corners:

```text
ABC
B B
CBC
```

Top corners:

* A

Bottom corners:

* C

Borders:

* B

---

### QuadD

Corners:

```text
ABC
B B
ABC
```

Left corners:

* A

Right corners:

* C

Borders:

* B

---

### QuadE

Corners:

```text
ABC
B B
CBA
```

Diagonal corners:

* A and C

Borders:

* B

---

## How does QuadChecker identify a Quad?

For every position in the rectangle:

1. Determine what character should be there according to Quad rules.
2. Compare it with the actual input.
3. If a mismatch is found, that Quad is rejected.
4. If every character matches, that Quad is accepted.

---

## Why don't we use quadA.go, quadB.go, etc.?

The subject only provides the output of those programs.

QuadChecker should work independently.

Instead of executing:

```bash
./quadA
```

we recreate the Quad rules inside our checker.

This makes the program:

* Faster
* Simpler
* Independent from external files

---

## Why not compare strings directly?

An older solution could generate an entire rectangle and compare strings.

Example:

```go
quadA(5,3) == input
```

This works but creates unnecessary strings.

The optimized solution compares characters directly in the grid.

Benefits:

* Less memory usage
* Faster execution
* Cleaner logic

---

## Why can multiple Quads match?

Some rectangles produce identical outputs.

Example:

```text
A
```

For a 1×1 rectangle:

* QuadC
* QuadD
* QuadE

all generate the same result.

Therefore QuadChecker prints all matches.

---

## What happens if no Quad matches?

Output:

```text
Not a quad function
```

Example:

```bash
echo "hello" | go run .
```

Result:

```text
Not a quad function
```

---

## What is the time complexity?

The checker scans every cell once for each Quad.

If width = W and height = H:

```text
O(W × H)
```

Since there are only five Quads, performance remains very fast.

---

## Common Reviewer Questions

### Why use strings.Join?

To combine multiple matches:

```go
strings.Join(matches, " || ")
```

Example:

```text
[quadC] [1] [1] || [quadD] [1] [1]
```

---

### Why return early in main?

Example:

```go
if len(matches) == 0 {
    fmt.Println("Not a quad function")
    return
}
```

This avoids unnecessary nesting and keeps the code cleaner.

---

### Why use helper functions?

Functions like:

* readInput()
* parseGrid()
* findMatches()

separate responsibilities and make the code easier to maintain and debug.

---

## Summary

QuadChecker:

* Reads a rectangle from stdin.
* Finds its width and height.
* Converts it into a grid.
* Checks the rules of QuadA-E.
* Prints all matching Quads.
* Prints "Not a quad function" when no match exists.


## Note
A reviewer is also very likely to ask:
"Why did you choose to compare character-by-character instead of generating the full rectangle?"

A good short answer is:
"Generating full rectangles creates extra strings and allocations. By comparing characters directly in the grid, I can reject invalid quads immediately and avoid unnecessary memory usage."

That answer usually shows you understand both the problem and the optimization.
